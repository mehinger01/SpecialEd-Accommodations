# CHANGE_REQUEST.md
# Parser Boundary Fixes and Student Page UX

## Objective

The parser is very close to correct.

The latest JSON output reveals two remaining extraction defects and one workflow usability issue.

This change request addresses only:

1. Accommodation title boundary detection
2. Location extraction
3. Student page accommodation visibility

Do not change:

- Upload workflow
- Student deletion
- Document deletion
- Accommodation deletion
- Section 6 whitelist logic
- Page 1 parsing
- Dashboard statistics

---

# Issue 1: Location Text Is Bleeding Into Accommodation Names

## Current Incorrect Output

Examples:

```text
General and Special Education Reduced writing
```

```text
General and Special Education Behavior Intervention Plan
```

## Root Cause

The title assembly logic is scanning backward from Start Date and incorrectly including location text as part of the accommodation title.

The parser is currently assembling:

```text
General and Special Education
Reduced writing
```

into:

```text
General and Special Education Reduced writing
```

instead of:

```text
Reduced writing
```

The same issue occurs with:

```text
Behavior Intervention Plan
```

---

## Required Behavior

Location text must never become part of an accommodation title.

The following text should be treated as a location value:

```text
General and Special Education
```

and never as part of the title.

Expected result:

```json
{
  "accommodationName": "Reduced writing",
  "location": "General and Special Education"
}
```

and

```json
{
  "accommodationName": "Behavior Intervention Plan",
  "location": "General and Special Education"
}
```

# Issue 2: Location Extraction Is Not Working

## Current Problem

All current records show:

```json
{
  "location": null
}
```

even when the source text clearly contains:

```text
General and Special Education
```

multiple times.

---

## Required Behavior

When any of the following patterns are detected:

```text
General and Special Education
```

```text
General
and
Special
Education
```

```text
General and Special
Education
```

normalize them into:

```text
General and Special Education
```

and store:

```json
{
  "location": "General and Special Education"
}
```

Remove the location text from:

- accommodationName
- description

after extraction.

# Issue 3: Student Page Hides Accommodations

## Current Problem

The Student page shows:

```text
Active Accommodations: 0
```

while simultaneously showing:

```text
8 pending review
```

and a linked document.

A normal user will assume no accommodations were found.

The user must discover that accommodations are hidden behind a linked document.

This is not intuitive.

---

## Required Behavior

Display accommodation counts directly on the Student page.

Example:

```text
Pending Accommodations: 8
Approved Accommodations: 0
```

If accommodations exist but are not yet approved:

Show a section:

```text
Pending Accommodation Review
```

with the accommodation list directly visible.

Do not force the user to click through a document link to discover accommodations.

---

## Student Page Display Rules

If accommodations exist:

Display:

- Pending count
- Approved count

If pending accommodations exist:

Display the accommodation list directly.

If approved accommodations exist:

Display them in the Active Accommodations section.

The Student page should become the primary accommodation view.

The document page should remain the detailed review view.
